# Agent Surface Experiment Plan v0.1

Status: READY

## Objective

Characterize multiple agent surfaces using one epistemic protocol while preserving product independence.

## Phase 1 — Immediately accessible / low-friction

Run or inspect:
- OpenClaw local runtime;
- GitHub Copilot Cloud Agent;
- Cursor Cloud Agents, if account access is available.

Reason:
These surfaces expose clear execution boundaries for local control, repository-scoped coding, and isolated cloud development.

## Phase 2 — General agent surfaces

Prepare:
- OpenAI Dots;
- Claude;
- Perplexity Computer;
- Manus.

Run the shared A0-A10 suite with product-specific extensions.

## Phase 3 — Enterprise surfaces

Prepare:
- Microsoft 365 Copilot Cowork;
- Gemini Enterprise Agent Platform.

Focus on governance, connector trust, delegated permissions, and auditability.

## Phase 4 — Cross-surface comparison

Do not produce a quality ranking.

Instead compare:

- execution substrate;
- state ownership;
- persistence semantics;
- authority boundary;
- permission model;
- connector model;
- computer-use path;
- background execution;
- interruption semantics;
- observability;
- receiptability;
- reproducibility;
- rollback path;
- model interchangeability.

## Cross-surface experiment

Give the same read-only repository reconnaissance task to at least three surfaces.

Record:
- exact prompt;
- repository revision;
- environment;
- action trace;
- returned claims;
- evidence;
- unsupported claims;
- final receipt.

Then independently verify all factual repository claims against the repository.

The purpose is to measure interface and execution differences, not to select a winning product.

## End state

The resulting artifact is an Agent Surface Characterization Map:

surface
  -> contract
  -> observations
  -> receipts
  -> verification
  -> limitations
  -> integration boundary

This becomes an input to Open-System-One's replaceable runtime architecture.
