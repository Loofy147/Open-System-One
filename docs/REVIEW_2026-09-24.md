# Research Review — 2026-09-24

This review reconciles the conversation history, local experiment artifacts, deployed lab state, and the repository foundation.

## What the project is

Open System One is an implementation-independent typed decision substrate:

Opaque State + Independent Typed Questions + Finite Outcome Spaces -> Batched Probabilistic Decisions -> Calibration -> Deterministic Policy.

It is not a reproduction of Jev and does not claim access to proprietary Jev weights.

## External architecture used as research input

TypeSafe publicly describes System One and Jev as structured decision models that return typed decisions and probabilities rather than generated text. The public primitives are Choice, Score, and Noul. Laya is an open implementation family exposing similar typed decisions with bidirectional encoder plus decision-head designs.

These projects define useful mechanisms and comparison points. They do not define this repository's canonical contract.

## Contract decisions retained

- State is opaque to the decision core.
- A request may contain multiple independent questions.
- Questions are keyed by stable IDs.
- Choice has a finite unordered outcome set.
- Score has an ordered level set.
- Noul is binary.
- Probabilities are closed and finite.
- Confidence is derived information, not truth.
- The model cannot directly invoke tools or side effects.
- Policy, authority, and execution are separate.
- Backends and runtimes are replaceable.
- Batch evaluation is first-class.

## Executed research

### Primitive sweep

A single-primitive sweep recorded 12/12 basic execution and contract probes as passing. This establishes implementation viability only.

An initial pair sweep covered 66 pairs. Only a small subset had registered interaction hypotheses; the remainder stayed OPEN rather than being mislabelled as negative.

One measured composition result: composition plus memoization preserved the composed result while removing repeated computation in the toy probe.

### Synthetic architecture sweep

The original architecture grid compared pairwise, marker/shared-context, and set-aware mechanisms at interaction 0 and 1.25, with K 2, 8, and 16.

Representative K=8, interaction=1.25:
- pairwise: accuracy 0.796875, Brier 0.0245269425
- marker: accuracy 0.5859375, Brier 0.0559512228
- set-aware: accuracy 0.734375, Brier 0.0283647478

A separate learned bidirectional transfer surrogate at K=8, interaction=1.25:
- pairwise: accuracy 0.5520833, Brier 0.0580787
- marker: accuracy 0.5416667, Brier 0.0628578
- set-aware: accuracy 0.5833333, Brier 0.0564166
- conditional: accuracy 0.5520833, Brier 0.0595144

These are synthetic or transfer results, not pretrained real-NLP benchmark evidence.

### Shortlist sweep

Oracle-vector test:
- N=128
- K=4 retained 3.125 percent of candidates; recall@1 ranged 0.9609375 to 0.98046875
- K=8 retained 6.25 percent; recall@1 was 1.0, 0.99609375, 0.99609375
- K=16 retained 12.5 percent; recall@1 was 1.0 for all three seeds
- K=32 and K=128 were also lossless in the recorded oracle test

This is a scalability proof of concept. Because the representation is oracle vectors, it is not evidence about real encoder retrieval.

### Real encoder browser transfer

The local environment lacked cached pretrained checkpoints, Transformers, and ONNX Runtime. Local model/package downloads also failed because outbound DNS/network resolution was unavailable. An AppDeploy backend attempt to bundle Hugging Face Transformers failed. The execution architecture was therefore moved to browser-side Transformers.js using ONNX, WebGPU when available, and ONNX/WASM fallback.

The browser lab then produced a user-supplied 384-dimensional MiniLM decision receipt.

### Twelve-case browser benchmark

The user supplied a 12-case receipt:
- pairwise accuracy 0.6666667
- set-aware accuracy 0.6666667
- conditional accuracy 0.6666667
- pairwise Brier 0.7242291
- set-aware Brier 0.7241934
- conditional Brier 0.7410993
- ECE 0.4147721 / 0.4114232 / 0.4238094 respectively

The historical mixed-K uniform Brier reference was 0.7916667. Later review found that a single baseline derived from mean K is not exact; exact skill must be computed per K.

The first permutation flip metric was also found invalid and corrected in the browser implementation.

## Failures and constraints

- Local environment: PyTorch available; transformers, ONNX Runtime, sentence-transformers, and tokenizers unavailable.
- Local outbound network resolution failed for model/package downloads.
- Hugging Face Jobs returned 402 Payment Required.
- AppDeploy backend bundling of Hugging Face Transformers failed.
- An intermediate benchmark had function-name shadowing that caused self-recursion; fixed.
- An intermediate benchmark used an escaped literal newline instead of the intended newline; fixed.
- An early probability path allowed non-finite values to leak; fixed in the earlier package.
- A conformal validation path did not reject NaN correctly; fixed in the earlier package.
- A permutation metric incorrectly looked for nonexistent reverse rows; fixed.
- The current browser BANKING77 pilot still has measurement debt: approximate mixed-K Brier baseline and prototype construction from the first five training examples.
- AppDeploy later blocked the statistical correction because the daily Free-tier deployment-credit threshold had been reached.

## Current frontier

The main unresolved question is not which scorer wins on one average.

It is:

Does candidate-set interaction materially improve a typed decision system on real data after controlling representation, candidate construction, K, hard negatives, and model/training budget?

Next discriminating matrix:

representation x candidate-set regime x K x scorer

with exact per-K metrics and a reviewed receipt.
